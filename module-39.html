39Revenue Operations

Build a revenue system that tells the truth.

Design stages around customer evidence, measure flow and conversion, calibrate forecasts, and use data for decisions rather than surveillance.

45 min lesson + practiceEvidence-led professional curriculumLevel 5
In this module
  • 1. Design the revenue architecture
  • 2. Define stages by buyer evidence
  • 3. Measure flow
  • 4. Forecast probabilistically
  • 5. Run commercial experiments
  • 6. Artifact: revenue operating system

1. Design the revenue architecture

Map market, demand, acquisition, onboarding, retention, expansion, and advocacy. Define ownership, handoffs, service levels, system of record, governance, and feedback loops across marketing, sales, success, finance, and product.

2. Define stages by buyer evidence

A stage represents an observable change in the customer’s decision process, with entry evidence, exit evidence, aging expectation, and allowed regressions. Seller activity alone—demo delivered, proposal sent—does not prove progress.

3. Measure flow

Track creation, conversion, velocity, age, slippage, loss, re-entry, and cohort quality. Segment only when samples support interpretation. Pipeline coverage is an output of rates and timing, not a universal multiplier.

4. Forecast probabilistically

Use historical base rates, current customer evidence, deal risks, and judgment. Compare predicted probabilities with outcomes using calibration: deals called 70% should win near 70% over a meaningful set. Benchmark against simple baselines and measure bias.

5. Run commercial experiments

Write a hypothesis, assignment unit, success and guardrail metrics, sample and duration logic, and decision rule before launch. Beware seasonality, selection, regression to the mean, and simultaneous changes. Label causal limits.

6. Artifact: revenue operating system

Deliver a lifecycle map, stage dictionary, metric tree, funnel cohort, forecast calibration table, experiment brief, dashboard wireframe, and weekly cadence.
